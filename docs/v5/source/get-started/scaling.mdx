## 一条命令，任意规模

v5 把分布式藏在 `DistributedConfig` 后面：训练代码按单机程序读，
Ray actor 承担分布式执行。

```bash
# 单卡：默认 local 模式
swift sft --model Qwen/Qwen3.5-4B --tuner lora --dataset 'swift/self-cognition#600' ...

# 单机多卡：Ray 模式
swift sft --mode ray --nproc_per_node 8 \
    --model Qwen/Qwen3.5-4B --tuner lora --dataset 'swift/self-cognition#600' ...
```

- `--mode ray` 每次运行启动隔离的本地 Ray head，worker 加载同一份 checkout；
  不要误连他人集群——每个 run 拥有自己的 head。
- 多机：先跨节点组 Ray，再把 run 指过去，见
  [`examples/v5/train/multi-node`](https://github.com/modelscope/ms-swift/tree/main/examples/v5/train/multi-node)。
- 并行度旗标（`--tensor_model_parallel_size`、`--pipeline_model_parallel_size`、
  `--expert_model_parallel_size`、序列并行）作用于 Megatron 后端；
  transformers 后端以数据并行 + ZeRO/FSDP 式分片扩展。

## Megatron 后端

超大 dense/MoE 模型走 Megatron 路径（权重经 mcore-bridge 转换）：

```bash
swift sft --backend megatron \
    --tensor_model_parallel_size 4 --pipeline_model_parallel_size 2 \
    --model Qwen/Qwen3-30B-A3B --tuner lora ...
```

可运行参考：`examples/v5/train/megatron/{tp_pp,moe}`。

## 经验法则

选能放下的最小放置，然后扩展同一份脚本——绝不按规模分叉 recipe。
某个配置只在一种规模下能跑，那是待报告的缺陷，不是值得照抄的模式。
