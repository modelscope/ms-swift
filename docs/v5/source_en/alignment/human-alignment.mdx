title: Human Alignment
description: Offline preference optimization (DPO/KTO/CPO/ORPO/SimPO) and reward models.
---

All offline preference algorithms run through `swift rl --rlhf_type <algo>` on
preference data — no sampler, no rollouts:

```bash
swift rl \
    --rlhf_type dpo \
    --model Qwen/Qwen3.5-4B \
    --dataset 'hjh0119/shareAI-Llama3-DPO-zh-en-emoji#10000' \
    --tuner lora --lora_rank 8 --lora_alpha 32 --target_modules all-linear \
    --torch_dtype bfloat16 --attn_impl flash_attention_2 \
    --beta 0.1 \
    --num_train_epochs 1 --learning_rate 1e-4 \
    --output_dir output
```

| Algorithm | Data shape | Key knob |
|---|---|---|
| `dpo` | chosen / rejected pairs | `--beta` (KL strength) |
| `kto` | single responses + binary desirable flag | `--beta` |
| `cpo` / `orpo` / `simpo` | chosen / rejected pairs | algorithm-specific loss flags |
| `rm` | chosen / rejected pairs → scalar reward head | used later by PPO |

- Preference rows: messages plus `chosen`/`rejected` continuations (KTO: a
  boolean label). Layouts in `examples/v5/rl/data`.
- These are supervised-style runs: judge them by loss and eval preference
  accuracy, not reward curves.
- Scale with `--mode ray --nproc_per_node N` like SFT.
- Runnable references: `examples/v5/rl/{dpo,kto,cpo,orpo,simpo,rm}`.
