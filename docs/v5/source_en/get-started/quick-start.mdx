SWIFT is ModelScope's framework for training, inference, and deployment of large language and multimodal models. v5 splits its underlying capabilities into the twinkle component library: twinkle provides the model, data, sampling, and distributed components, while SWIFT assembles training workflows on top and exposes them through the CLI, Python API, and WebUI. twinkle also provides multi-tenant server/client capabilities, so training and sampling can be deployed as a service and driven from any machine.

**Why SWIFT v5?**

- **Write single-machine code, train at any scale**: the same training code scales from one GPU to a cluster, with distribution and rollout scheduling driven by configuration.
- **Model coverage**: training, inference, and deployment for 600+ text-only and 400+ multimodal models, with Day0 support for trending models.
- **Training techniques**: lightweight tuning with LoRA/QLoRA/DoRA, SFT/pretraining, preference learning with DPO/KTO/CPO, and online RL and distillation algorithms such as GRPO, PPO, and GKD.
- **Three training backends**: transformers, Megatron, and remote service (twinkle-server) share one CLI and Python API.
- **Datasets**: 150+ built-in datasets plus custom JSONL data; templates handle encoding and loss masks.
- **Hardware support**: NVIDIA GPUs, AMD GPUs, Ascend NPUs, Apple MPS, and CPUs.
- **Training as a service**: deploy twinkle-server on a compute machine and train large models without a local GPU.

## Installation

Choose packages for your needs; you do not need to install everything on the same machine. An isolated Python 3.12 environment is recommended.

### Local training with SWIFT

Install SWIFT v5 on the training machine. twinkle is installed as a dependency, so no separate installation is needed:

```bash
pip install 'ms-swift>=5.0.0'
```

See [Installation](./installation.mdx) for environment requirements, [Docker](./docker.mdx) for containers, and [Models and Datasets](./models-and-datasets.mdx) for selection and data sources.

The local examples use NVIDIA GPUs, BF16, and the FlashAttention 2 kernel. Install PyTorch compatible with your driver and CUDA environment, plus flash-attn (`pip install flash-attn --no-build-isolation`).

```bash
# A simple sft example
CUDA_VISIBLE_DEVICES=0 \
swift sft \
    --model Qwen/Qwen3.5-4B \
    --attn_impl flash_attention_2 \
    --dataset 'swift/self-cognition#600' \
    --model_name swift-robot \
    --model_author swift \
    --gradient_accumulation_steps 8 \
    --learning_rate 1e-4 \
    --max_length 2048 \
    --save_steps 100 \
    --save_total_limit 2 \
    --output_dir output/sft
```

```python
# pip install vllm
import math

from swift.dev.builders import build_prompt_dataloader, resolve_rl_dp_size
from swift.dev.config import (
    CheckpointConfig, DatasetConfig, DistributedConfig, ModelConfig, RLConfig, RewardConfig,
    RolloutConfig, TemplateConfig, TrainConfig, TunerConfig)
from swift.dev.recipe.distill.assembly import (
    DISTILL_SIGNALS, build_distill_driver, distill_group_requests, initialize_distill_cluster)
from swift.dev.recipe.offload import sleep_for_rollout
from swift.dev.recipe.utils import (
    effective_colocate, initialize_rl_devices, optimizer_batch_slices, prompt_rows_from_dataset,
    stream_batch_size)
from swift.dev.utils.scoring import copy_inputs


def main():
    model_config = ModelConfig(model='Qwen/Qwen3.5-4B', attn_impl='flash_attention_2')
    template_config = TemplateConfig(max_length=8192)
    dataset_config = DatasetConfig(dataset=['AI-MO/NuminaMath-TIR#2000'])
    train_config = TrainConfig(
        max_steps=20, per_device_train_batch_size=4, learning_rate=2e-5, gradient_checkpointing=True)
    distributed_config = DistributedConfig(mode='ray', nproc_per_node=2)
    checkpoint_config = CheckpointConfig(output_dir='output/mopd')
    generation_batch_size = 16  # prompts rolled out per batch
    rollout_config = RolloutConfig(
        sampler_mode='colocate', vllm_gpu_memory_utilization=0.5,
        generation_batch_size=generation_batch_size)
    # Two frozen teachers score the student's own rollouts; the weights are normalized to sum 1.
    rl_config = RLConfig(
        rl_type='mopd', teacher_model=['Qwen/Qwen3.5-4B', 'Qwen/Qwen3.5-9B'],
        teacher_weights=[0.7, 0.3], lmbda=1.0, num_generations=1, sampling_temperature=1.0,
        max_completion_length=2048)

    # 1. Prompts: the rows the student rolls out on.
    prompt_rows, prompts, prompt_extras = prompt_rows_from_dataset(dataset_config)

    # 2. Devices: the template, the device-group plan and twinkle (Ray) itself.
    template, resource_plan, teacher_meshes = initialize_rl_devices(
        model_config=model_config, template_config=template_config, dataset_config=dataset_config,
        train_config=train_config, distributed_config=distributed_config,
        checkpoint_config=checkpoint_config, rollout_config=rollout_config, rl_config=rl_config,
        reward_config=RewardConfig(), tuner_config=TunerConfig(),
        output_dir=checkpoint_config.output_dir, prompt_rows=prompt_rows,
        group_requests=lambda: distill_group_requests(rl_config))

    # 3. Cluster: the student (LoRA), the vLLM sampler, the frozen teachers, and the worker that
    #    turns each teacher forward into the training signal.
    train_batch_size = train_config.per_device_train_batch_size * resolve_rl_dp_size(distributed_config)
    batch_size = stream_batch_size(
        colocate=effective_colocate(rollout_config, resource_plan),
        generation_batch_size=generation_batch_size, num_generations=rl_config.num_generations,
        train_batch_size=train_batch_size,
        gradient_accumulation_steps=train_config.gradient_accumulation_steps)
    cluster = initialize_distill_cluster(
        model_config=model_config, template_config=template_config, template=template,
        train_config=train_config, distributed_config=distributed_config,
        checkpoint_config=checkpoint_config, rollout_config=rollout_config, rl_config=rl_config,
        tuner_config=TunerConfig(), max_steps=train_config.max_steps,
        signal=DISTILL_SIGNALS['mopd'], train_batch_size=train_batch_size, batch_size=batch_size,
        resource_plan=resource_plan, auxiliary_meshes=teacher_meshes)

    # 4. Driver: streams the student's rollouts, `batch_size` rows per batch.
    dataloader = build_prompt_dataloader(
        prompts, prompt_extras, seed=dataset_config.data_seed,
        shuffle=dataset_config.train_dataloader_shuffle, batch_size=generation_batch_size)
    driver = build_distill_driver(
        cluster=cluster, rl_config=rl_config, rollout_config=rollout_config,
        prompt_dataloader=dataloader, batch_size=batch_size,
        num_train_epochs=math.ceil(train_config.num_train_epochs),
        max_steps=train_config.max_steps * train_batch_size // batch_size)

    # 5. Loop: roll out, score with the teachers, update, publish the weights to the sampler.
    cluster.engine.sync_weights()
    for trajs, _ in driver:
        if cluster.colocate:  # hand the GPUs back from the sampler
            sleep_for_rollout(cluster.sampler, rollout_config.sleep_level)
            cluster.model.reload_to_gpu()
        for lo, hi in optimizer_batch_slices(len(trajs), train_batch_size, 1):
            update = trajs[lo:hi]
            signal = dict(cluster.worker.forward_kwargs(update, True))
            cluster.model.forward_backward(
                inputs=copy_inputs(update), gradient_accumulation_steps=1,
                micro_batch_size=train_config.per_device_train_batch_size, **signal)
            cluster.model.clip_grad_and_step(
                max_grad_norm=train_config.max_grad_norm, gradient_accumulation_steps=1)
            print(cluster.model.calculate_metric(is_training=True))
        cluster.engine.sync_weights()
    driver.close()


if __name__ == '__main__':
    main()
```

The examples use the `Qwen/Qwen3.5-4B` model. SWIFT downloads models through ModelScope by default. Add `--use_hf true` to SWIFT commands to use Hugging Face.

### Remote training with a client

Install the lightweight client on the machine submitting training work. The server manages model weights and GPU computation; the client does not need a local GPU:

```bash
pip install 'twinkle-kit[client]'
```

## Remote training

Deploy a single-GPU LoRA training service, then perform a few SFT updates from a client. The server and client can run on different machines.

### Deploy twinkle-server

On the GPU machine, save the following as `server_config.yaml`:

```yaml
http_options:
  host: 127.0.0.1
  port: 8000
persistence:
  mode: memory
applications:
  - name: server
    route_prefix: /api/v1
    import_path: server
    args:
      supported_models:
        - Qwen/Qwen3.5-4B
  - name: models-Qwen3.5-4B
    route_prefix: /api/v1/model/Qwen/Qwen3.5-4B
    import_path: model
    args:
      backend: transformers
      model_id: ms://Qwen/Qwen3.5-4B
      model_loader: swift.dev.model.loader:build_model_loader
      train_mode: lora
      min_replicas: 1
      max_replicas: 1
      nproc_per_node: 1
      max_loras: 2
      max_r: 32
      max_length: 2048
      mixed_precision: bf16
      gradient_checkpointing: true
      device_group:
        name: model
        ranks: 1
        device_type: cuda
      device_mesh:
        device_type: cuda
        dp_size: 1
```

In a fresh serving environment, start Ray and then the service:

```bash
CUDA_VISIBLE_DEVICES=0 ray start --head --num-gpus=1
twinkle-server launch --config server_config.yaml
```

If a Ray cluster already exists, connect to it instead of starting another head. Wait for the service to become ready, then run the client in another terminal.

This configuration deploys only the training model and gateway, using one training GPU without an independent sampler. `max_loras` limits the number of LoRA adapters per model instance; `max_r` is the maximum permitted rank.

The example listens only on localhost. For access from another machine, configure a protected network entry point and authentication before changing the host to `0.0.0.0`. `/api/v1` is the service prefix used by the client.

### Train from the client

The client encodes text and sends inputs such as tokens and labels to the server. This example additionally uses Transformers and PEFT for tokenizer and LoRA configuration preparation:

```bash
pip install transformers peft
```

Save the following as `client_sft.py`:

```python
import os
from peft import LoraConfig
from transformers import AutoTokenizer
from twinkle_client import init_twinkle_client

model_id = 'Qwen/Qwen3.5-4B'
tokenizer = AutoTokenizer.from_pretrained(model_id)
prompt_ids = tokenizer.apply_chat_template(
    [{'role': 'user', 'content': 'Who are you?'}],
    tokenize=True,
    add_generation_prompt=True,
)
answer_ids = tokenizer.encode(
    'I am swift-robot, developed by swift.' + tokenizer.eos_token,
    add_special_tokens=False,
)
tokens = prompt_ids + answer_ids
inputs = [{
    'input_ids': tokens[:-1],
    'labels': [-100] * (len(prompt_ids) - 1) + answer_ids,
    'attention_mask': [1] * (len(tokens) - 1),
    'position_ids': list(range(len(tokens) - 1)),
}]

with init_twinkle_client(
    base_url=os.environ.get('TWINKLE_SERVER_URL', 'http://127.0.0.1:8000'),
    api_key=os.environ.get('TWINKLE_SERVER_TOKEN'),
) as client:
    model = client.model(model_id)
    try:
        model.add_adapter_to_model(
            'default',
            LoraConfig(r=8, lora_alpha=32, target_modules='all-linear'),
            gradient_accumulation_steps=1,
        )
        model.set_processor('InputProcessor')
        model.set_loss('CrossEntropyLoss')
        model.set_optimizer('Adam', lr=1e-4)
        for step in range(10):
            model.forward_backward(inputs=inputs)
            model.clip_grad_and_step(max_grad_norm=1.0)
            print(step + 1, model.calculate_metric().result)
        checkpoint = model.save('quick-start', save_optimizer=True)
        print(checkpoint.twinkle_path)
    finally:
        model.close()
```

Run:

```bash
python client_sft.py
```

This tokenizer example fetches tokenizer files from Hugging Face without downloading base model weights. `labels` are already aligned with the next token; `-100` excludes prompt positions so only the answer is trained. Repeating one sample illustrates the API; use your own dataset and batches for real training.

For access from another machine, set `TWINKLE_SERVER_URL` to the server address. With authentication enabled, provide the server-issued credentials through `TWINKLE_SERVER_TOKEN`. The returned `twinkle://` URI identifies a server-side checkpoint, not a client-side file path.
