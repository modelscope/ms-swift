SWIFT v5 packages are split by machine role, so you do not need to install everything on the same machine. Use an isolated Python 3.12 environment and run installation commands in the Python environment that will execute training or serving.

| Package | Role | Where to install |
|---|---|---|
| `ms-swift` | CLI and Python API for training, inference, deployment, and evaluation | Local training machines; clients that submit with `--mode remote` |
| `twinkle-server` | Multi-tenant training and sampling service | Machines providing GPU compute |
| `twinkle-client` | Python SDK and CLI for remote training | Machines that submit training jobs without a local GPU |

## Wheel installation

### Local training with SWIFT

Install SWIFT on the training machine; its dependencies are installed with it. The examples in [Quick Start](./quick-start.mdx) do not require `twinkle-server` or `twinkle-client`:

```bash
# Install SWIFT v5
pip install 'ms-swift>=5.0.0'

# Optional dependencies
pip install 'ms-swift[megatron]'  # Megatron backend: installs mcore-bridge and megatron-core; requires a matching CUDA environment, so it is not part of all
pip install 'ms-swift[eval]'  # Evaluation: installs evalscope with the opencompass / vlmeval backends
pip install 'ms-swift[all]'  # All optional dependencies: eval (excluding megatron)

# Install with uv, which selects the PyTorch build matching your device
pip install uv
uv pip install 'ms-swift>=5.0.0' --torch-backend=auto
```

### Deploy twinkle-server

Install on the machine providing GPU compute. The server configures models, samplers, and resources, and clients submit training operations through it. `swift deploy` requires `ms-swift` on the same machine:

```bash
pip install twinkle-server ms-swift
```

See [Remote Training & twinkle-server](../interfaces/server-client.mdx) for the full deployment procedure.

### Remote training with a client

Install on the machine submitting training jobs. The client does not need a local GPU:

```bash
pip install twinkle-client ms-swift
```

Add `--mode remote` when submitting remote training through SWIFT commands; `ms-swift` and `twinkle-client` must be installed in the same Python environment.

## Source installation

For development branches or local modifications, clone the repository and install it into the same Python environment:

```bash
git clone https://github.com/modelscope/ms-swift.git
cd ms-swift
pip install -e .
uv pip install -e . --torch-backend=auto  # With uv
```

After installation, the examples in [Models and Datasets](./models-and-datasets.mdx) run directly.

## Images

See [Docker](./docker.mdx) for Docker images with SWIFT, PyTorch, and inference engines preinstalled, and for container startup. Images still require host drivers and a device runtime. Mount persistent model and dataset caches to avoid downloading them again after recreating a container.

## Runtime environment

| Component | Range | Recommended | Notes |
|---|---|---|---|
| python | `>=3.11,<3.14` | 3.12 | |
| cuda | | | Not required for CPU, NPU, or MPS |
| torch | `>=2.6,<3.0` | | Select the CUDA / ROCm / NPU build for your device |
| transformers | `>=5.8,<6.0` | | |
| datasets | `>=4.0,<4.8.5` | | |
| peft | `>=0.11,<0.20` | | Lightweight tuning such as LoRA |
| trl | `>=0.15,<1.0` | | RL |
| ray | `>=2.55` | | Distributed execution and the server |
| flash_attn | | | The NVIDIA BF16 examples use FlashAttention 2 |
| vllm | | | Online sampling / deployment |
| sglang | | | Online sampling / deployment |

Install in this order: first a [PyTorch](https://pytorch.org/get-started/locally/) build compatible with the device and driver (CUDA, ROCm, and NPU builds are not interchangeable), then SWIFT, and finally attention kernels and inference engines. Engine installation can also change PyTorch, Transformers, and other dependencies, so select compatible training and inference versions within the same isolated environment.

Install FlashAttention 2 after PyTorch and a working CUDA build environment are available:

```bash
pip install packaging ninja
pip install flash-attn --no-build-isolation
```

The examples on this site select `--attn_impl flash_attention_2`. On hardware without FlashAttention, choose an implementation supported by the model and platform rather than copying CUDA installation commands. See [requirements/install_all.sh](https://github.com/modelscope/ms-swift/blob/main/requirements/install_all.sh) for more optional dependencies.

## Supported hardware

| Hardware | Notes | Reference |
|---|---|---|
| NVIDIA GPUs | Supported by default; examples on this site use NVIDIA GPUs with BF16 | — |
| AMD GPUs | Use ROCm-enabled PyTorch | [AMD Support](https://github.com/modelscope/ms-swift/blob/main/docs/v4/source_en/BestPractices/AMD-support.md) |
| Ascend NPUs | Install torch-npu matching CANN and the Ascend extension required by the inference engine | [NPU Support](https://github.com/modelscope/ms-swift/blob/main/docs/v4/source_en/BestPractices/NPU-support.md) |
| MetaX GPUs | | [MetaX Support](https://github.com/modelscope/ms-swift/blob/main/docs/v4/source_en/BestPractices/Metax-support.md) |
| Moore Threads MUSA GPUs | | [MUSA Support](https://github.com/modelscope/ms-swift/blob/main/docs/v4/source_en/BestPractices/MUSA-support.md) |
| Apple MPS | Local inference or small training jobs with compatible models | [issue](https://github.com/modelscope/ms-swift/issues/4572) |
| CPUs | Local inference or small training jobs with compatible models | — |

Models, inference engines, and parallel backends have different hardware requirements; GPU-specific samplers and kernels cannot be reused directly on CPUs or MPS.

## Notebook environment

Most models supported by SWIFT for training run on an `A10` GPU. You can use the free GPU instance provided by ModelScope:

1. Sign in to the [ModelScope](https://www.modelscope.cn) website.
2. Click **My Notebook** in the left sidebar and start a free GPU instance, then install SWIFT inside the instance as described above.
