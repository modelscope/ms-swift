## 镜像来源

ModelScope 的 SWIFT 镜像构建配置见[镜像构建脚本](https://github.com/modelscope/modelscope/blob/build_swift_image/docker/build_image.py)。镜像名称包含操作系统、CUDA、Python、PyTorch、vLLM、ModelScope 和 SWIFT 版本。

以下为 v4 安装文档列出的同一镜像在三个地域的地址：

```text
modelscope-registry.cn-hangzhou.cr.aliyuncs.com/modelscope-repo/modelscope:ubuntu22.04-cuda13.0.3-py312-torch2.13.0-vllm0.28.0-modelscope1.40.0-swift4.5.3
modelscope-registry.cn-beijing.cr.aliyuncs.com/modelscope-repo/modelscope:ubuntu22.04-cuda13.0.3-py312-torch2.13.0-vllm0.28.0-modelscope1.40.0-swift4.5.3
modelscope-registry.us-west-1.cr.aliyuncs.com/modelscope-repo/modelscope:ubuntu22.04-cuda13.0.3-py312-torch2.13.0-vllm0.28.0-modelscope1.40.0-swift4.5.3
```

选择距离运行环境较近的 registry。该标签预装 SWIFT 4.5.3；用作 v5 基础环境时，在容器中安装 SWIFT v5。镜像中的驱动相关依赖仍须与宿主机兼容。

## 启动容器

宿主机应安装 NVIDIA 驱动、Docker 和 NVIDIA Container Toolkit。下面将模型缓存与训练输出挂载到宿主机目录：

```bash
mkdir -p "$HOME/.cache/modelscope" "$PWD/output"
IMAGE=modelscope-registry.cn-hangzhou.cr.aliyuncs.com/modelscope-repo/modelscope:ubuntu22.04-cuda13.0.3-py312-torch2.13.0-vllm0.28.0-modelscope1.40.0-swift4.5.3
docker run --gpus all --ipc=host -it \
    -e MODELSCOPE_CACHE=/cache/modelscope \
    -v "$HOME/.cache/modelscope:/cache/modelscope" \
    -v "$PWD/output:/workspace/output" \
    -w /workspace \
    "$IMAGE" bash
```

在容器内执行：

```bash
pip install 'ms-swift>=5.0.0'
```

然后运行[快速启动](./quick-start.mdx)的 SFT 或 GRPO 示例。采样器、数学奖励及其他任务依赖按对应示例安装。

## 服务端容器

安装服务端依赖：

```bash
pip install twinkle-server
```

将 `server_config.yaml` 挂载到容器，按[远程训练文档](../interfaces/server-client.mdx)启动 Ray 和 twinkle-server。跨容器访问需要映射服务端口，并配置监听地址、鉴权和网络入口；默认监听本机的配置不会自动对其他容器开放。

## 缓存与资源

- 给 `MODELSCOPE_CACHE` 挂持久卷，模型权重不随容器重建丢失。切换 Hugging Face 时另外挂载其缓存目录。
- 输出目录包含 checkpoint、日志和指标，应挂持久卷。客户端返回的远程 checkpoint URI 不等于客户端容器的本地路径。
- `--ipc=host` 使用宿主机共享内存。隔离部署也可以使用独立共享内存配置；Ray 和推理引擎需要足够共享内存。
- 容器只看到分配给它的 GPU；示例中的 `CUDA_VISIBLE_DEVICES` 应按容器内设备编号设置。
- 多机服务必须保证节点间通信可达，并统一模型路径和版本。镜像相同不代表资源放置配置自动相同。

AMD、NPU 等平台的设备映射和运行时不同，按[硬件支持](./installation.mdx)中的平台资料准备环境。
